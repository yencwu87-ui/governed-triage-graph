# governed-triage-graph

A support-ticket triage system built as an explicit LangGraph state machine,
with the governance controls as first-class nodes rather than wrappers.

The point is not the classifier. The point is that **the control plane is
separable from the model** — the whole graph runs with the model swapped out,
so the governance can be tested independently of the thing it governs.

## The graph

```
ingress ──▶ retrieve ──▶ classify ──▶ [Gate A] ──▶ route ──▶ [Gate B] ──▶ audit
    │                                     │                     │
    └────────────▶ escalate_ungrounded ◀──┘                     │
                                              human writes to state
```

**Gate A — machine safety.** A conditional edge. Refuses to auto-proceed below
a confidence floor or with no precedent. Evaluated by the machine alone.

**Gate B — human accountability.** A LangGraph `interrupt()`. Every `high` call
halts the graph. Execution suspends, state is checkpointed, and nothing
proceeds without a human writing a decision into state. The checkpoint records
who resumed it and whether they agreed.

Those are two different things and most systems conflate them. An eval score
is not an audit trail; a signature is not accountability.

## Results

**Scope.** These runs score the `classify` step in isolation. The graph is
bypassed — no retrieval, no Gate A, no Gate B. This is deliberate: the
classifier is the component the governance is meant to constrain, so it is
measured naked first. Graph-level numbers are a separate experiment and are
not reported here.

**Labels.** Scored against the corpus's generator-assigned labels, not the
hand-labelled gold set. The gold set (n=100) is not yet populated enough to
score against. This distinction matters for reading the result below.

**Split.** One stratified 75/25 split, `random_state=0`, produced by
`eval_harness.baseline()`. Every run is scored on the same 4,085 held-out
rows. Held-out class balance is 843 low / 1,655 medium / 1,587 high, giving a
**majority-class floor of 0.4051**.

**Leakage.** The LoRA training file (`finetune/data/train.jsonl`, 12,938 rows)
was checked against the held-out set by exact text match. Overlap: **0 of
12,938**. See `check_leakage.py`.

| run | accuracy | macro-F1 | κ | under-class. | cost/ticket |
|---|---|---|---|---|---|
| majority-class floor | 0.4051 | — | 0.000 | — | 0 |
| TF-IDF + logistic regression | 0.6404 | 0.6091 | 0.4233 | 0.1386 | sub-ms |
| llama3.1-8b 4-bit + rubric v0.1 | 0.4203 | 0.3772 | 0.0823 | 0.2392 | ~1.0 s |

Thresholds: accuracy ≥ 0.700, macro-F1 ≥ 0.650, **Cohen's κ ≥ 0.200**,
under-classification ≤ 0.200. Both runs FAIL.

The LLM ran locally via `mlx_lm.server` at `temperature=0.0`, prompted with
`rubric.md` plus an output-shape instruction. Full test set: 70 minutes.
79 of 4,085 responses (1.9%) could not be parsed and were recorded as `low` —
see Findings 5. Repeated baseline runs vary by ~0.2 accuracy points
(0.6421 / 0.6404), which sets the noise floor. The 22-point gap is two orders
of magnitude larger.

**Read the confusion matrix, not the headline.** The baseline's population-wide
under-classification of 13.9% clears the ceiling while it under-scores 30.8% of
genuinely high-priority tickets. Population metrics hide asymmetric failure.

**The LLM performs at chance.** Its accuracy sits 1.5 points above the
majority-class floor — a model answering `medium` to every ticket without
reading any of them would have scored 0.4051. κ = 0.08 confirms it directly.
It is not collapsing to one class: its prediction marginals (14.7 / 39.9 /
45.4) track the true distribution (20.6 / 40.5 / 38.8) more closely than the
baseline's do. It produces a sensible spread of answers and attaches them to
the wrong tickets.

Per-class recall:

| class | baseline | LLM |
|---|---|---|
| low | 0.375 | 0.168 |
| medium | 0.726 | 0.427 |
| high | 0.692 | 0.547 |

Cost belongs in the same row as accuracy or the comparison is dishonest. Three
to four orders of magnitude more compute, 22 points worse.

## Open question

The labels are demonstrably learnable — TF-IDF plus logistic regression reaches
κ = 0.42, so signal exists in the text. They appear not to be *derivable from a
severity rubric*, since a model reasoning from one lands at κ = 0.08.

Two explanations remain open and the accuracy figures do not separate them:

1. An 8B model cannot perform this task from a rubric alone.
2. The priority labels were generated by a process correlating with vocabulary
   rather than severity. A bag-of-words model reverse-engineers that generator.
   A model reasoning about severity has no way to guess it.

If (2) holds, LoRA fine-tuning should recover most of the gap, because it is
the right tool for teaching a labelling function a model cannot infer. **This
is a hypothesis, recorded before the result is known.** Also outstanding: a
qualitative read of disagreement cases, and a graph-level run with retrieval
enabled to test whether grounding moves κ.

## Run it

```bash
pip install -r requirements.txt
python make_datasets.py          # see DATA.md — corpus is not in this repo
streamlit run app.py             # visual test bench
```

The test bench has three modes: single-ticket trace, batch with confusion
matrix, and blind gold-set labelling. Stub mode runs the full control plane
with placeholder node bodies, so the gates can be exercised with no API key.

```bash
python eval_harness.py --baseline
python check_leakage.py
python run_triage.py --ticket TK00042
```

Reproducing the LLM run — the server needs its own terminal and an environment
with MLX installed:

```bash
mlx_lm.server --model mlx-community/Meta-Llama-3.1-8B-Instruct-4bit --port 8080

python predict_mlx.py --model mlx-community/Meta-Llama-3.1-8B-Instruct-4bit \
                      --out preds_base.csv
python eval_harness.py --preds preds_base.csv --label "llama3.1-8b base + rubric"
```

## Findings

Things this build surfaced, kept here because negative results are the point.

1. **Rejected the first corpus.** The UCI/Kaggle ServiceNow event log (141,712
   rows, 24,918 incidents) turned out to have no free-text field, `cmdb_ci`
   99.7% missing, and a `priority` that matched the ITIL impact×urgency matrix
   **100.0% of the time** — a lookup table, not a judgement, with 95% of
   incidents sitting at the Medium/Medium default. Predicting it would have
   been predicting a formula. Killed at diligence, before any build.

2. **The eval suite had a blind spot, and only a bad model exposed it.** The
   original gates were accuracy, macro-F1 and under-classification. All three
   fired FAIL on the LLM run — but they also fired FAIL on the baseline. A run
   performing at chance and a run with moderate genuine agreement produced the
   same verdict, and nothing in the output distinguished them. Cohen's κ was
   added afterwards and separates them cleanly (0.42 vs 0.08). Evaluation
   frameworks need adversarial cases to validate them. A passing run would
   never have surfaced this.

3. **Checkpoint serialisation is undeclared.** LangGraph warns that the Pydantic
   models in state are unregistered msgpack types and will be refused in a
   future version. The Gate B approval record depends on that checkpoint, so the
   audit trail currently rests on a deprecation-flagged format. Open.

4. **Confidence may not be measuring anything.** Gate A routes on the model's
   self-reported confidence. If the distribution is narrow, the gate is
   decorative. Checked explicitly rather than assumed — see `WIRE_IN.md`.

5. **Parse failures are handled differently in the graph and in the eval.**
   In the graph, a malformed classifier response flags and halts — a silent
   fallback passes evals and fails in production. In the offline eval path
   halting is not available, since every row must carry a label, so failures
   are recorded as `low`, which penalises the model on the gated
   under-classification metric. Dropping them would remove the rows the model
   handled worst and flatter the result. The divergence is deliberate and the
   rate is reported (1.9%).

## Limitations

- Results cover the `classify` node only. The graph, retrieval and both gates
  are bypassed in these runs.
- Corpus is synthetic and its labels are generator-assigned. See `DATA.md`.
- Customer support, not ITIL incidents. "Priority" means commercial urgency.
- Retrieval similarity is lexical; no embedding model is wired in yet.
- No per-node cost or latency instrumentation yet. Cost figures above are
  wall-clock at the process level.
- Gold set is n=100, single annotator, no inter-rater agreement — and is not
  yet used for scoring.
- The LLM run is a single prompt configuration with no few-shot examples and
  no prompt iteration. It is a floor, not a ceiling.
